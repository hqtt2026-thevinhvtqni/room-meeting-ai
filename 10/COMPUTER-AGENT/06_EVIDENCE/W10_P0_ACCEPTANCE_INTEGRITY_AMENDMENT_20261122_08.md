## 2. Response to An's V7 findings

### AN-V7-F01 — Caller-authored consistency flags are not proof

V8 must remove caller authority over consistency claims. The semantic validator must independently compute all expected/observed comparisons. It must never accept `outcome_match`, `state_match`, or `validator_result` merely because those booleans/strings appear in a submitted manifest.

Proposed validator attestation record:
- validator_id and validator_version;
- validator_source_sha256 / executable_sha256;
- input_manifest_sha256;
- execution_id and runner_identity;
- output_artifact_ref and output_artifact_sha256;
- category_outcome_policy_id and category_outcome_policy_sha256;
- per-rule computed results and final validator verdict;
- trusted-runner provenance/attestation reference.

The validator output must be generated by the trusted runner after it hashes the input bytes. The validator must recompute all matches, resolve every artifact reference, hash actual artifact bytes, and validate fixture identity against observed host inventory. A manifest-supplied attestation is not self-authenticating. The consumer must verify the referenced output artifact and trusted-runner provenance before accepting PASS.

Disposition: DESIGN RESPONSE PROPOSED; validator NOT IMPLEMENTED / NOT RUN.

### AN-V7-F02 — UNKNOWN lease/owner state must not pass

For any verdict PASS:
- observed.lease_state must be RELEASED or HELD; UNKNOWN is prohibited.
- observed.owner_state must be CURRENT, FENCED or NONE; UNKNOWN is prohibited.
- if a category truly has no applicable lease/owner concept, it must use an explicit, reviewed NOT_APPLICABLE representation in the V8 state model rather than UNKNOWN or an invented value.
- category-specific acceptance rules must determine whether HELD, RELEASED, CURRENT, FENCED, NONE or NOT_APPLICABLE is correct. Do not impose one universal value across all test categories.

V8 schema proposal must encode the non-UNKNOWN constraint wherever possible; the semantic validator must enforce the category-specific expected state.

Disposition: DESIGN RESPONSE PROPOSED; schema and validator not implemented.

### AN-V7-F03 — Category/outcome compatibility and forged flags

A test verdict PASS means the test's declared acceptance oracle passed. It does not mean observed.outcome must literally equal PASS: for example, a negative protocol test may correctly observe REJECTED, and a process-containment test may correctly observe TERMINATED.

Therefore V8 must not use a simplistic universal outcome enum rule. It must introduce a versioned, hash-pinned category outcome policy mapping each test.category and test_id family to its allowed expected/observed terminal outcomes and state tuple. The validator must:
1. load the pinned policy from a trusted source;
2. recompute expected-versus-observed state comparisons;
3. reject outcomes not allowed for the test category;
4. reject PASS when expected and observed differ, even if submitted flags claim true;
5. reject PASS when observed state violates the category's terminal-state oracle;
6. record policy ID/hash and per-rule outcomes in validator evidence.

Disposition: DESIGN RESPONSE PROPOSED; category policy requires An review before implementation.

### AN-V7-F04 — Negative catalogue and validator execution evidence absent

The V8 negative catalogue must include at minimum:
- forged outcome_match=true with expected/observed outcome mismatch;
- forged state_match=true with lease/owner/process/containment mismatch;
- missing, stale, or mismatched validator executable hash;
- input manifest hash mismatch;
- missing validator output artifact or output artifact hash mismatch;
- missing trusted-runner provenance;
- PASS with UNKNOWN lease_state;
- PASS with UNKNOWN owner_state;
- category-disallowed observed outcome with verdict PASS;
- category-disallowed expected/observed state tuple with verdict PASS;
- artifact reference points to NA, absent or hash-mismatched bytes;
- fixture manifest/hash/host-build/architecture mismatch;
- unsupported profile attempting PASS;
- unknown category policy ID/hash;
- validator timeout/crash/malformed output.

These are test specifications only. No schema validator or semantic validator has been executed.

Disposition: DESIGN RESPONSE PROPOSED; validation remains BLOCKED / NOT RUN.

## 3. V8 schema and validator boundary

V8 should require a `validator_attestation` object and reference its output artifact, but JSON Schema alone cannot authenticate the runner, recompute hashes, compare arbitrary values, or prove that a file reference resolves to actual bytes.

The trusted semantic validator is the authority for:
- exact input manifest hash;
- exact schema hash and validator build hash;
- trusted runner identity/provenance;
- expected/observed equality;
- category/outcome policy compatibility;
- artifact and fixture byte hashes;
- terminal-state and cleanup semantics;
- rejection of UNKNOWN states for PASS;
- per-rule results and a final verdict.

No caller-provided consistency flag may substitute for these computations. The validator's own evidence must be retained independently and re-verifiable.

## 4. Timeout semantics and process-isolation boundary
